# Instructions for Claude (read this first)

This repo is Harshal's personal watch archive. He updates it by chatting with Claude; Claude edits the data and pushes.

## Layout
- `data/library.json`: one JSON object per line. Fields: `id`, `title`, `original` (non-English original title, if any), `type` (`show`|`film`), `shelf` (`tv`|`anime`|`film`), `year` (films), `w` episodes watched, `s` status (0 Watching, 1 Finished, 2 Backlog, 3 Dropped), `f` favourite 0/1, `r` rating 1-10 (0 = none), `x` film rewatch count, `n` note, `last` ("S5E9"), `seq` recency order.
- `data/tmdb.json`, `data/episodes.json`: generated by the Action. Never hand-edit.
- `data/overrides.json`: fix a wrong TMDB match: `{"<item id>": {"k": "tv"|"movie", "t": <tmdb id>}}`.
- `index.html`: read-only viewer. `scripts/`: tooling.

## Doing what he asks
Use the CLI, never hand-edit library.json:
- `node scripts/add.mjs film "Title" 2026 [--alt "English title"] [--status 1]`
- `node scripts/add.mjs show "Title" [--anime] [--eps N] [--status 0]`
- `node scripts/add.mjs set "Title" w+=10 r=9 f=1 x=1 s=1 n="note"`
`add` refuses an exact-title duplicate (check before assuming a title is new; near-matches like "The Devil Wears Prada" are different titles). `set` with `w` or `+=` bumps `seq`, so touched titles rise in "Recently added".
Verify uncertain titles or years with a web search first. Then commit and push to `main`; the workflow fetches TMDB data and Pages redeploys in a couple of minutes.

## Rules
- Never change an existing `id` (progress is keyed to it; ids come from `makeId` in `scripts/lib.mjs`).
- Don't overwrite his ratings, favourites, notes or rewatch counts when adding other things.
- No secrets in the repo. `TMDB_KEY` lives in GitHub Actions secrets.
- The sandbox cannot reach TMDB; only the Action can. Don't try to work around that.
- Style he wants: concise, direct, mobile-friendly replies.
